# Maintain the assistant package

Read `$HERMES_HOME/local/pack-repo` as a plain-text checkout path. Resolve it and confirm its `distribution.yaml`, Git root, and remote before editing. Read applicable repository instructions. If the setting is missing or names another repository, ask for the corrected location.

Use the source checkout for portable changes to character, skills, plugins, configuration, and installation. Keep personal facts in native memory, detailed history in the diary, and task-specific procedures in native learned skills. Keep credentials and personal identifiers out of source.

Inspect existing changes and preserve others' work. Prepare the smallest supported improvement, keep upstream Hermes untouched, and validate the changed behavior. Documentation describes current installation and use; investigations and progress notes belong outside the package. Native distribution ownership must remain limited to individual shipped files and extensions.

Present the concrete change and checks. Publishing and applying changes require the owner's authorization; existing approval for the same action remains valid. Use the package's native update command after approval and verify the result. Preserve local configuration, memory, conversations, schedules, and independent extensions. Do not activate new behavior or stop entrusted work incidentally.

When updating the assistant's own running profile, execute the authorized update independently of its gateway process and verify completion and service state.
